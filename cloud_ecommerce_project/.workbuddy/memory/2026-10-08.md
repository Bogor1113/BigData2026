### 新增

### 修复的真实缺陷
| 文件 | 问题 |
|---|---|
| bin/ods_etl_scripts.sh | `while [ ... ]:` 多一个冒号，`first` 模式必挂；无失败退出；无日志；无参数校验 |
| dwd/dwd_clean_data.sh | 靠 `--hiveconf ${par}` 字符串巧合工作；`show partitions` 表头靠 `!= "partition"` 硬过滤 |
| dws/dws_user_day_snapshot.sh | 无 shebang，无参数/日志 |
| dws/dws_user_day_snapshot.sql | 每天 `dt <= 目标` 全历史重扫；select 第 7 列写的是 total_order_amount，与列名 total_pay_amount 错位 |
| dws/dws_user_topic_wide.sql | `payment_time is not null or !=''` 恒真；金额中位数 `cast(... as bigint)` 丢小数；三个偏好表 inner join 会丢用户 |
| ads/ads_user_daily_report.sql | `insert into` 非幂等；`first_order_date is not null or !=''` 恒真；除零无保护；`current_date` 无法补跑 |
| bin/ods_etl_checkdata.sh | 只比条数且输出文件固定路径互相覆盖，diff 结果不可读 |

### 关键设计决策
- **统一时间基准**：所有脚本 `dt` 参数 = 数据日期（正常调度为昨天），替代原 SQL 里的 `current_date`，使补跑可复现。
- **DWS 日快照改增量**：`当天 dwd 分区 + 前一天快照累计`（full join 叠加），计算量从 O(全历史) 降到 O(当天)；口径不变。首次/回补用 `full` 模式。
- **ADS 表改 stat_date 分区 + insert overwrite**，DataX 侧 path 加 `stat_date=${stat_date}` 并用 `index:-1` 固定值列补回分区列。
- 校验脚本升级为逐表比对并输出 `logs/ods_check_result_<date>.txt`，失败返回 1。

### 自测方式与结果
本地无 Hadoop 环境，用 mock（假 hive/hadoop/mysql/python3）+ 临时项目副本实跑验证：
9 个用例全通过 —— 增量默认昨天、first 补数循环 3 天、all、DWD all 逐分区、错误参数/缺参/缺文件拦截、命令失败中断并透传退出码；
自查中额外发现「2026-13-99 形状合法但日期不存在」绕过正则校验，已用 `date -d` 回验修复。

## 追加：数据质量规则集（P0 项 A）

主人确认工程化成熟度约 40%，选定先补 P0 中的「数据质量」一块。

### 新增 `dq/` 目录
- `dq/dq_rule_check.sql`：19 条字段级规则，用 `UNION ALL` 汇总成统一结果集（分组/规则名/异常数/说明），异常数=0 即通过。
  - ODS 8 条：主键唯一（用户/商品/订单）、手机号格式、必填字段空值、当日分区为空、金额勾稽（订单表 `总额-优惠+运费=实付`、明细表 `单价*数量=明细总额`，容差 0.01）
  - DWD 4 条：当日分区为空、订单商品重复、应付金额为负、必填为空
  - DWS 3 条：当日分区为空、用户重复、累计小于当日
  - ADS 2 条：当日分区为空、转化率为负
  - CROSS 2 条：DWD 订单未在 ODS 中（用 `EXCEPT`，两边 order_id 先 cast 成 string）、ADS 订单量与 DWS 宽表不一致
- `dq/dq_check.sh`：执行规则集 → 生成 `logs/dq_report_<date>.txt` 质量报告 → 有失败则 exit 1。

### 自测（mock hive 注入结果集）
4 个场景通过：含失败规则（2 条 FAIL，退出码 1）、全部通过（退出码 0）、规则集返回空（**主动判定失败**，防静默通过）、报告文件落盘。
自查中发现并修掉两处：中文用 `printf %-28s` 按字节对齐会错位（改为朴素 `[PASS]/[FAIL] A | B | 异常 N` 格式）；`total=0` 原本会误判为通过（已加防护）。
